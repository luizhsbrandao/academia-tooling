# academia-tooling

A conformance checker for `.docx` academic manuscripts (ABNT NBR 14724 and journal-specific
rule sets) and an auditor for `.bib` bibliographies. Built for Brazilian journal submissions,
where a desk rejection over a margin, a spacing or a missing reference entry costs months.

The design rule is **no guessing**: every numeric limit comes from `normas.json` next to a
citable source. When the norm does not fix a parameter — or the document does not declare it —
the verdict is `NAO_VERIFICAVEL`, never `PASS`. A check that cannot fail is not a check.

> Português: [README.pt-BR.md](README.pt-BR.md) — documentação completa, com o detalhe de cada checagem.

## Why another checker

Manuscript rules are partly citable and partly not. NBR 14724 fixes margins (3/2 cm), body size
(12 pt) and spacing (1.5), but it does not fix a typeface family or a word limit. Most tools fill
that silence with a default and then report "compliant" for something nobody verified.

This one refuses to guess, in three ways:

1. **`normas.json` rejects a limit without a source.** A value with an empty `fonte` fails at load
   time (`NormaInvalida`). "Never guess" is code, not advice.
2. **The exit code separates the two kinds of silence.** "The norm doesn't say" exits `0`.
   "The norm says, but this document doesn't let me check" exits `3` by default.
3. **`PASS` cannot coexist with material deviation.** Typeface, size and spacing are compared on
   the *effective* formatting (direct run/paragraph formatting wins over the `Normal` style); more
   than 10 % of the body outside the declared pattern is a `FAIL` with the counts in the verdict.

## Install

Python ≥ 3.11. One runtime dependency: `python-docx`.

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]"

# synthetic .docx fixtures (generated, never read from a private corpus)
.venv/bin/python -m academia_tooling.fixtures tests/fixtures/gerados
```

## Usage

```bash
# manuscript conformance
./check_docx.py --arquivo manuscrito.docx --norma abnt
./check_docx.py --arquivo manuscrito.docx --norma rbcs --json
./check_docx.py --arquivo manuscrito.docx --norma regn --normas meu_edital.json

# bibliography, optionally cross-checked against the text
./check_bib.py --bib referencias.bib
./check_bib.py --bib referencias.bib --texto artigo.tex
./check_bib.py --bib referencias.bib --docx manuscrito.docx --estrito
```

### Exit codes — `check_docx.py`

| code | meaning |
|---|---|
| 0 | no `FAIL`, and nothing was left unverified *for lack of a limit in the norm* |
| 1 | at least one `FAIL` |
| 2 | usage error: missing/corrupt `.docx`, unknown norm, invalid `normas.json` |
| 3 | a check could not verify **the document** (nothing declared, exact spacing, blind heuristic) — or any `NAO_VERIFICAVEL` under `--estrito` |

Every `NAO_VERIFICAVEL` carries `motivo_nao_verificavel ∈ {norma, documento}`:
`norma` means the norm is silent (exit `0`, the right answer), `documento` means the norm is
explicit but the file does not allow verification (exit `3`). Not verified is not approved, and
the exit code does not treat the two as equal.

### Exit codes — `check_bib.py`

`0` no `ERRO` (warnings allowed) · `1` at least one `ERRO` (or any `AVISO` with `--estrito`) ·
`2` usage error.

## Your own rule set

Embedded norms: `abnt` (NBR 14724:2011), `rbcs` (word range only, from the journal guidelines),
`regn` (nothing citable — every check deliberately answers `NAO_VERIFICAVEL`).

For a call for papers, copy `normas.exemplo.json`, fill the limits from the edital with the
source quoted, and pass it with `--normas`. Limits the edital does not fix stay `null`.

`normas.json` is a record, not case law: check the norm edition in force and the call for papers
before treating a report as final.

## What it does not do

Only `.docx` (no `.doc`/`.odt`/`.pdf`). It checks *who* was cited, not *how* (no NBR 10520/6023
style validation). Footnote and numeric citation systems are not read. Tables, headers/footers,
footnotes and text boxes are outside word counting and citation extraction. Theme-only fonts
(`theme1.xml`) cannot be resolved by `python-docx` and surface as `NAO_VERIFICAVEL`. Nothing about
argument quality, plagiarism, spelling or scope. The full list, with the reasoning for each gap,
is in [README.pt-BR.md](README.pt-BR.md#o-que-não-é-coberto).
